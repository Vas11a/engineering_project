# Первый запуск Lexilo

Приложение реализует MVP из плана: личные словари и карточки, четыре режима обучения, адаптивные повторения, сохранение сессий, статистику, общий каталог, копирование наборов, Telegram-бота и AI-перевод с подтверждением перед сохранением.

## Что нужно подготовить

| Настройка backend         | Откуда взять                                                           |
| ------------------------- | ---------------------------------------------------------------------- |
| `DATABASE_URL`            | Pooled connection string из Neon                                       |
| `DATABASE_URL_UNPOOLED`   | Direct connection string той же базы Neon                              |
| `TELEGRAM_BOT_TOKEN`      | Создать бота через `@BotFather` → `/newbot`                            |
| `AI_API_KEY`              | Ключ OpenAI API; нужен только для AI-перевода                          |
| `TELEGRAM_WEBHOOK_SECRET` | Придумать случайный секрет: например, выполнить `openssl rand -hex 32` |

Все ключи остаются на сервере. При деплое одним проектом Vercel frontend обращается к API на том же домене, поэтому `VITE_API_URL` задавать не нужно. Эта переменная нужна только для отдельного адреса backend. Не присылай токены в чат и не добавляй их в Git.

## Сначала проверить локально

1. Скопируй `backend/.env.example` в `backend/.env`, а `frontend/.env.example` — в `frontend/.env`. Если `.env` уже есть, дополни его вручную, сохранив существующие значения.
2. Заполни адреса базы и токен бота. Оставь `DEV_AUTH_ENABLED=true`, `DEV_TELEGRAM_ID=100000001` и `BOT_MODE=disabled` для проверки в обычном браузере. AI-ключ можно пока не добавлять.
3. В терминале backend выполни:

```bash
cd backend
npm ci
npm run prisma:generate
npm run db:deploy
npm run db:check
npm run dev
```

4. Во втором терминале из корня проекта:

```bash
cd frontend
npm ci
npm run dev
```

Открой [http://localhost:5173](http://localhost:5173). Создай набор и несколько карточек с разными переводами. После первого правильного ответа повторение назначается через день, после ошибки — через десять минут. Для новых учебных сессий добавляй новые карточки или жди срока повторения.

Чтобы локально проверить ответы бота на `/start`, задай `BOT_MODE=polling`, выполни `npm run bot:setup` из backend и перезапусти backend. Без `MINI_APP_URL` бот отвечает текстом, а интерфейс проверяется отдельно в браузере. При `BOT_MODE=disabled` работает только API, поэтому бот не получает команды. Для кнопки открытия приложения внутри Telegram понадобятся публичные HTTPS-адреса frontend и backend; адрес `localhost` на телефоне для этого не подходит.

## Затем запустить внутри Telegram

1. Импортируй `Vas11a/engineering_project` в Vercel из ветки `main`. Оставь **Root Directory `./`** и **Application Preset `Services`**. Готовый `vercel.json` собирает frontend и backend вместе на одном домене. Services доступен в Beta на всех планах, включая Hobby.
2. В Production environment variables добавь `NODE_ENV=production`, `DEV_AUTH_ENABLED=false`, `BOT_MODE=webhook`, оба адреса базы, токен бота и случайный `TELEGRAM_WEBHOOK_SECRET` длиной 16–256 символов. Не копируй локальные `DEV_AUTH_ENABLED=true` и `BOT_MODE=polling` в облако.
3. `MINI_APP_URL` и `PUBLIC_API_URL` на Vercel выводятся из `VERCEL_PROJECT_PRODUCTION_URL`, с резервным `VERCEL_URL`. Их можно явно задать как один стабильный HTTPS-адрес проекта. `CORS_ORIGIN` также определяется автоматически; при явной настройке укажи origin проекта без завершающего `/`. `VITE_API_URL` оставь незаданным.
4. Примени недостающие миграции отдельной командой `npm run db:deploy` из backend с direct-подключением к целевой базе. Сборка Vercel сама схему базы не меняет. После успешного деплоя проверь `/health` и `/ready` на домене проекта.
5. Останови локальный polling. В локальном окружении с тем же токеном, секретом, `BOT_MODE=webhook` и явными Production-адресами выполни `npm run bot:setup` из backend. Команда зарегистрирует команды, кнопку открытия приложения и webhook на Vercel.
6. Напиши боту `/start` и открой приложение его кнопкой. Production-домен должен быть доступен Telegram без входа в Vercel; защиту Preview-деплоев можно сохранить. В обычном браузере без Telegram-входа приватное API возвращает `401` — это ожидаемо.

Подробно: [Vercel Services — настройки и проверка](VERCEL.md). Раздельный вариант Render + Vercel описан в [альтернативной инструкции](DEPLOYMENT.md).

Для AI-перевода добавь `AI_API_KEY`; по умолчанию заданы `AI_BASE_URL=https://api.openai.com/v1` и `AI_MODEL=gpt-5-mini`. У API-проекта должны быть доступ к модели и настроенная оплата. Без ключа карточки по-прежнему создаются вручную. Альтернатива через Neon AI Gateway описана в полном руководстве.

Изменения переменных backend требуют перезапуска сервера, а `VITE_API_URL` — новой сборки frontend. Не запускай локальный polling и production-webhook с одним токеном одновременно.

Полная [инструкция Vercel и проверки на устройстве](VERCEL.md), [описание API](API.md), [архитектура и алгоритм повторений](ARCHITECTURE.md), [автоматические проверки](TESTING.md).

Локальная проверка кода не подтверждает успешный облачный деплой. После каждого релиза проверяй readiness, запуск внутри Telegram и, при подключённом AI-ключе, реальное создание перевода.
